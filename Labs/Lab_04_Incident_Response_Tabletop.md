# Lab 04 — Incident Response Tabletop

## Objective

Run a structured tabletop exercise for a simulated ransomware incident.

SY0-701 objective alignment: 4.1 Incident Response and Handling

## Scenario

A finance endpoint reports file encryption activity and suspicious outbound traffic.

## Roles

- Incident commander
- SOC analyst
- System owner
- Communications lead
- Compliance/legal observer

## Step-by-Step Procedure

1. Preparation:
   - Define assumptions and available evidence.
   - Set severity criteria and escalation contacts.
2. Detection and analysis:
   - Classify incident type and probable scope.
   - Identify high-value affected assets.
3. Containment decision:
   - Choose short-term containment and justify tradeoffs.
4. Eradication and recovery plan:
   - Identify root cause hypothesis.
   - Define restoration order and validation checks.
5. Post-incident activity:
   - Capture lessons learned and assign action owners.

## Validation Checkpoints

- Incident timeline with clear decisions and timestamps
- At least three evidence sources listed
- At least three concrete control improvements assigned

## Tasks

1. Classify incident severity.
2. Define immediate containment steps.
3. Identify evidence to collect first.
4. Plan eradication and recovery actions.
5. Produce post-incident lessons learned.

## Troubleshooting Tips

- Team disagreement: use pre-defined severity matrix to guide calls.
- Missing data: document assumptions explicitly.
- Action drift: appoint one facilitator to keep phase boundaries clear.

## Deliverable

- Timeline of response decisions
- One-page after-action report with control improvements

## Reflection Prompt

Which decision had the highest business-risk tradeoff, and would you change it?
